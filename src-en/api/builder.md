# Imperative Authoring (Builder / L)

**Module**: `deer_layout::builder` (available directly from the prelude)

## What it does

An imperative declaration API with an imgui feel: the call site is the widget, no boilerplate, chainable. Internally it maintains a **retained node tree** — layout, hit testing, and rendering all need the tree; only the submission style is "immediate". It shares the same deterministic id rules as [scene files](scene.md), and the two paths produce structurally equal trees (the core invariant; see [Step 2](../getting_started/step_by_step/02_builder.md)).

## `Builder` methods

| Method | Parameters | Returns | Notes |
|---|---|---|---|
| `Builder::new` | `(kind: Kind, id: impl Into<String>)` | `Builder` | An explicitly named root; the id gets "reserved" so auto ids never collide with it |
| `Builder::auto` | `(kind: Kind)` | `Builder` | The root id is generated by `IdGen` (matching the scene file's default behavior) |
| `.padding(v: f32)` | chained | `Builder` | Padding, applied **to the root node only** |
| `.gap(v: f32)` | chained | `Builder` | Child spacing, applied **to the root node only** |
| `.size(w, h)` | `(Option<Size>, Option<Size>)` | `Builder` | Explicit size, applied **to the root node only** |
| `.text(label)` | `impl Into<String>` | `String` (id) | Appends a `Text` leaf |
| `.button(label)` | same | `String` (id) | Appends a `Button` leaf |
| `.field(label)` | same | `String` (id) | Appends a `Field` leaf |
| `.text_opts(label, f)` / `.button_opts(label, f)` | `FnOnce(&mut Node)` | `String` (id) | Appends a leaf and **edits it in place** (e.g. `n.layout.wrap = true`) |
| `.container(kind, id, body)` | `FnOnce(&mut Builder)` | `()` | Container + closure nesting; asserts `kind` is `Column`/`Row` |
| `.container_auto(kind, body)` | same | `()` | Container + auto id |
| `.container_opts(kind, id, layout: LayoutProps, body)` | same | `()` | Container + layout props (the proper way to set layout on nested containers) |
| `.build()` | — | `Node` | **Clones** the whole tree; the `Builder` remains reusable |
| `.root_id()` | — | `&str` | The root's id |

## `L` — a `LayoutProps` convenience constructor

`L::new().…` chains setters, and `.to_props()` finally produces a `LayoutProps`:

| Method | Corresponding field | Notes |
|---|---|---|
| `.w(px)` / `.h(px)` | `width` / `height` = `Some(Size::Px(px))` | For percentages, insert `Size::Pct(p)` manually |
| `.pad(px)` / `.gap(px)` | `padding` / `gap` | |
| `.main(Align)` / `.cross(Align)` | `main_axis` / `cross_axis` | |
| `.grow(w)` | `grow` | Weight for distributing leftover main-axis space |
| `.scroll(bool)` | `scroll` | Vertical scroll container, **meaningful only on `Column`** (ignored on `Row`) |
| `.wrap(bool)` | `wrap` | Wraps text at width, **meaningful only on `Text`** |

There is also the free function `props(label: Option<&str>, disabled: bool) -> NodeProps`.

## Example

```rust
use deer_gui::prelude::*;

let mut app = Builder::new(Kind::Column, "app").padding(12.0).gap(8.0);
let ok_id = app.text("准备好了吗？");                    // keep the id for event handling
app.button_opts("取消", |b| { b.props.disabled = true; }); // edit props in place
app.container_opts(Kind::Row, "bar", L::new().gap(8.0).to_props(), |r| {
    r.button("确定");
});
let tree = app.build();
```

## Notes

- **Chained methods like `new().padding()` only affect the root node**; to set props on a nested container you must use
  `container_opts` + `L` — the most common point of confusion;
- **Ids drift with structure**: auto ids look like `text_1`, `button_1`, counted per kind. Give a node an explicit id whenever it will be located by id
  (events, script `move @id`);
- The order inside `_opts` / `container_with` is "set layout/props first, `with_id` last" —
  whole-struct assignment would overwrite the id. Follow the same order when constructing `Node` chains directly (a pitfall hit once);
- `build()` returns a clone; mutating the `Builder` afterwards does not affect a tree already `build()`-ed out;
- Events never enter the tree (the tree is pure data): what happens after a click is reported by id through the [interaction layer](interaction.md).
